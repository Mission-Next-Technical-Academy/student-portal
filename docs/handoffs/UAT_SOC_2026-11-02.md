## 1. How the UAT was run

- **Accounts:** one synthetic SOCAN student and one ADMIN grader, on **staging** (`bin/dev.sh`, served at `localhost:8768` and `127.0.0.1:8768`).
  - Account names are not written here because the repo is public. They are in the owner's password manager.
  - Agents can't sign in, so the owner signs in.
- **Browser:** Chrome driven over CDP (:9222) with Playwright, using real clicks and typing only. No JS injection or DB writes were used to pass any step.
- **Method for every module part:**
  1. Fill every input and save.
  2. **Wipe everything except the session token** (cookies, localStorage, IndexedDB, Cache Storage, service workers, HTTP cache, other sessionStorage keys).
  3. Hard refresh and confirm everything came back from the backend.
  4. Submit, with a double-click to test double submission.
  5. Grade as the instructor (Approve, or Return then resubmit) and confirm the student view.
- **Harness** (local only, not in the repo): `~/uat-screenshots/2026-11-02-soc/harness/`.
  - `act.js` steps include `wipe-all-but-token`.
  - `monitor.js` logs console and network errors.
  - `MODULE_AGENT_BRIEF.md` is the per-module subagent brief.
  - The raw run log is `docs/handoffs/UAT_SOC_E2E_HUMAN_2026-11-02.md` in `~/mnt-account-names` (untracked). It is reference only.
- **Harness lessons** (don't rediscover these):
  - CDP `Storage.clearDataForOrigin(local_storage)` **also clears sessionStorage**, which signs the tab out. Save the `sb-*-auth-token` and restore it after the wipe.
  - A Playwright client with no `dialog` listener auto-dismisses `confirm()` dialogs, and this applies even to other connections.
  - The student account allows at most 2 open sessions. Admin → Student Activity Monitor → Sign out clears stuck ones.
  - The idle sweep closes sessions idle for 60 min.
  - After a reload, lab sections start collapsed (U5). Open them before reading the DOM.

## 4. Owner decisions (not code bugs; each has a recommendation)

1. **U13: should students see "Attempt N of 2"?** Recommendation: yes. Show it next to Submit Lab, because Prove It attempts are capped.
2. **U16: should the Guided Lab get a grader entry?** Recommendation: no. Practice is auto-scored, so keep the grader for Prove It only. Document it in the grader guide.
3. **U18: leftover tabs in later consoles.** Recommendation: keep them, as they're cumulative tools. Label them "Optional in this module", or hide the ones the module's sheet doesn't read.
4. **U5 default:** restore the last open/closed state (#96 fixes the broken save and restore), or always open the incomplete lab. Recommendation: restore the last state.
5. **Track completion at 12/12:** no certificate, banner or badge shows. Recommendation: add a completion banner on the track page. A certificate is a product decision.
6. **U8 strength:** #96 ships a soft warning, so the second click submits anyway. Alternatively make it a hard block until the graded sections are non-empty.
7. **U43(d):** single revoke and restore targets in M12 are by design. Add decoy targets if the module should test target selection.
