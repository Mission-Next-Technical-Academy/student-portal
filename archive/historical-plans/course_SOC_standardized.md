Cybersecurity Course Standardization & UX Requirements

Objective

Standardize the course experience across Modules 1--12 while
preserving the strong content already present in Module 1.

The primary goals are to:

Reduce unnecessary scrolling.

Improve persistent progress tracking and navigation.

Standardize the instructional flow across modules.

Add concise video lectures where they improve learning.

Use randomized quiz banks rather than fixed question sets.

Align quiz tone and structure with CompTIA Security+ style.

Provide supporting sources and references throughout the course.

Build toward a comprehensive cyber-range capstone in Module 12.

1. Module Navigation & User Experience

Current Concerns

The Review Module button is always located at the bottom of the
module.

Students must repeatedly scroll through material they have already
completed to return to their current section.

Long learning sections make navigation less efficient than it should
be.

Recommended Changes

Review Module Button

Place a Review Module button at the top of every module
card/box, while retaining the bottom button if useful.

Students should be able to enter review mode immediately without
scrolling through the entire module.

Persistent Progress & Navigation

Add persistent module navigation that remains accessible while the
student works.

It should clearly show:

Current module

Current lesson/section

Completed sections

Current quiz/lab

Overall module progress

Quick navigation to previously completed sections

A clear Continue action for the next incomplete activity

A collapsible sidebar, sticky progress header, or similar interface
would work well.

Reduce Scrolling

Break long learning sections into smaller, clearly defined units rather
than presenting an entire module as one continuous page.

Suggested structure:

Lecture

Knowledge Check / Quiz

Lecture

Knowledge Check / Quiz

Lab

Module Review

Completed sections should be collapsible so students can focus on their
current task without losing access to previous material.

2. Standard Module Format

Modules 1--11 should follow a consistent instructional pattern:

Lecture → Quiz → Lab

Each module should contain:

Lecture

Teach the concepts required for the module using concise written
instruction and, where appropriate, a short video lecture.

Quiz

Immediately reinforce the lecture concepts with Security+-style
questions.

Lab

Require the student to apply the concepts in a practical or simulated
environment.

Module Review

Provide a concise review of the major concepts, terminology, objectives,
and areas the student should understand before continuing.

This structure should remain consistent throughout Modules 1--11 so
students always understand the learning rhythm.

3. Video Lecture Recommendations

Video lectures would be valuable, but they should remain focused and
relatively short.

Recommended Length

Approximately 8--15 minutes per lecture segment.

For larger topics, use several short lectures instead of one long video.

Example:

Lecture 1 --- Core Concept: 10 minutes

Quiz / Knowledge Check

Lecture 2 --- Applied Scenario: 12 minutes

Quiz / Knowledge Check

Lab

The videos should complement the written material rather than simply
reading it aloud.

Good lecture content should focus on:

Explaining difficult concepts

Walking through diagrams or architectures

Demonstrating tools or workflows

Connecting technical concepts to realistic security scenarios

Explaining how Security+ may test the concept

4. Quiz Design

The existing quizzes are useful, but fixed question sets should be
replaced or supplemented with question banks.

Question Bank Model

Each learning objective or concept should have multiple possible
questions.

When a student starts a quiz, the system should select questions from
the relevant concept bank.

If the student fails and retries:

The same concepts and objectives should be tested.

The student should receive different questions where possible.

Questions and answer choices may be randomized.

Difficulty should remain approximately equivalent between attempts.

The goal is to test whether the student understands the concept rather
than whether they memorized the previous answers.

Example

Concept:

Principle of Least Privilege

The question bank might contain several different scenarios testing the
same objective:

User permissions

Administrator privileges

Service accounts

Cloud IAM roles

Application permissions

A retry could therefore test the same underlying knowledge using a
different scenario.

5. Security+ Question Style

Quiz questions should consistently resemble the style and reasoning
approach expected on CompTIA Security+ without copying proprietary
exam questions.

Questions should emphasize:

Scenario-based reasoning

Selecting the BEST, MOST appropriate, or FIRST action

Identifying the correct security control

Applying security concepts rather than recalling definitions alone

Troubleshooting realistic security situations

Understanding architecture, operations, threats, vulnerabilities,
and governance

Distractors should be plausible rather than obviously incorrect.

Avoid excessive trivia or questions that depend primarily on memorizing
obscure facts.

6. Sources & Student References

Supporting sources should appear throughout the course where they help
students understand or verify a concept.

Useful authoritative sources may include:

CompTIA Security+ published exam objectives

NIST publications

CISA guidance

Microsoft security documentation

Vendor documentation

OWASP resources

MITRE ATT&CK

Other authoritative cybersecurity standards and documentation

References should support learning rather than overwhelm the lesson.

Where appropriate, include a short Further Reading or Sources
section at the end of a lecture or module.

7. Module 12 --- Capstone

Module 12 should intentionally break from the standard Module 1--11
structure.

Instead of several independent labs, Module 12 should prepare students
for and then deliver a complete cyber-range simulation.

Recommended Structure

Capstone Preparation Lectures

Short lectures covering:

Scenario orientation

Environment architecture

Rules of engagement

Available tools

Investigation methodology

Documentation expectations

Incident handling workflow

Final Cyber-Range Lab

Students should then complete an integrated scenario requiring them to
apply knowledge accumulated throughout the course.

The capstone should combine multiple Security+ concepts rather than
testing a single topic in isolation.

Possible activities include:

Reviewing alerts

Identifying suspicious activity

Examining logs

Evaluating vulnerabilities

Applying appropriate security controls

Making containment or remediation decisions

Documenting findings

Prioritizing actions

Producing an incident or security report

The capstone should feel like the culmination of Modules 1--11 rather
than another ordinary module lab.

8. Standardization Target

Module 1 is the quality baseline.

The existing Module 1 data and overall instructional approach are
strong. The remaining modules should be standardized around the same
level of quality while improving navigation and consistency.

Modules 1--11

Lecture → Quiz → Lecture/Quiz as needed → Lab → Review

Module 12

Capstone Lectures → Final Integrated Cyber-Range Simulation

Priority Changes

High Priority

Add Review Module access at the top of every module.

Implement persistent progress/navigation.

Reduce unnecessary scrolling through completed learning sections.

Standardize Modules 1--11 around Lecture → Quiz → Lab.

Replace fixed quizzes with randomized concept-based question banks.

Standardize quiz wording around Security+-style reasoning.

Make Module 12 a comprehensive cyber-range capstone.

Secondary Improvements

Add focused 8--15 minute video lectures.

Make completed sections collapsible.

Add authoritative sources throughout lessons.

Provide concise module reviews and further-reading resources.

Desired Student Experience

The student should always be able to answer three questions immediately:

Where am I?

What have I completed?

What do I do next?

The platform should minimize navigation friction so the student's
attention remains on learning and applying cybersecurity concepts rather
than repeatedly scrolling through course content.
